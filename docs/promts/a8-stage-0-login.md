## 1. Стан на момент старту — не перевідкривай

**D.4 закритий наполовину, і важливо розуміти, якою саме.** PR #108 дав вердикт
**✅ PASS на T470** (`~/hart`, 2026-09-13, exit 0, nonce повернувся дослівно, 0 входжень
`soft-denying`). Це доводить, що **механіка** headless-виклику працює: `agy -p` стартує,
читає `read_file`, пише `write_file`, нічого стороннього не чіпає.

Чого це **не** доводить: креденшали на T470 отримані через браузер. На A8 браузера немає,
і саме **логін** там досі відкритий. Різниця з тим, що було раніше: замість трьох варіантів
«спробуйте по черзі» тепер одна команда з однозначним exit-кодом.

**Той самий блокер стоїть і перед D.3** (`claude setup-token` на A8). У `PROGRESS.md`
це §4.10: «спосіб передачі OAuth-кодів не описаний ніде, блокує D.3». **Обидва кроки —
одна проблема:** браузерний OAuth на машині без браузера. Розв'яжеш раз — знімеш обидва.

**Де тепер живе операційна документація A8.** Приватний репозиторій
**`stjurik/a8-ops`** (заведено 2026-09-14, локально — `~/projects/a8-remote`): `PROGRESS.md`,
`A8_UBUNTU_INSTALL.md`, `REVIEW_SYNTHESIS_FULL.md`, `files/` — 30 файлів.

Туди ж пишуться результати цього прогону, у наявні розділи — **не заводь нових**:

- **`PROGRESS.md` §4.9 «Життєвий цикл токенів Track D»** — строки дії і процедура поновлення;
- **`PROGRESS.md` §4.10 «Headless-OAuth для D.3»** — робочий спосіб логіна, дослівно;
- `PROGRESS.md` §1 — таблиця стану, якщо щось із неї змінилось.

Розділення навмисне: продуктовий `flatcraft` публічний, а ці документи містять адреси
обох каналів доступу, правила фаєрвола, топологію tailnet і відбитки ключів. Класифікація
даних робиться межею репозиторію, не редагуванням тексту — тому **не переносить сюди**
нічого з них дослівно.

**Готові інструменти, не переписуй:** `check-agy-headless.sh` (вердикти 0-8),
`check-agy-scope.sh` (baseline-guard), `check-deny-parity.sh`, `prove-red-before-green.sh`.

## 2. Завдання A — межа worktree (ВИКОНАНО; преміса була хибною)

> **Цей розділ лишений як запис помилки, а не як інструкція.** Прогін 2026-09-15 закрив
> його і водночас спростував те, на чому він стояв.

**Що стверджувалось:** `agy` не працює з worktree поза `trustedWorkspaces`; зонд із
`~/hart-wt/...` дає exit 7; отже Gemini-пул (ADR-039 §5) і worktree-ізоляція (§2)
взаємовиключні.

**Що виміряно 2026-09-15 (4 виклики `agy`, кожен зі зміненою умовою):** `agy -p` відповідає
і виконує `read_file`/`write_file` навіть із теки, якої немає у списку **ні прямо, ні через
батька**. Контроль на кешування довіри — тека, якої у списку не було ніколи.

**Звідки брався exit 7:** з **нашого власного скрипта**. `check-agy-headless.sh` звіряв шлях
точним збігом і відмовлявся працювати **до** виклику `agy`. Ми виміряли поведінку свого
гейта і прийняли її за поведінку інструмента.

Додатково (перевірено окремо): та звірка була помилковою навіть за старої гіпотези —
`os.path.realpath(p) == target` відхиляє **будь-яку підтеку** довіреного кореня.

**Наслідок:** конфлікту немає, ADR-039 §5 ніколи не був зламаний, worktree можна тримати
будь-де під `$HOME/hart-wt`. `trust-worktree.sh` лишається **страховкою, не передумовою** —
він не блокує, `exit 2` прогін не валить. Не робити з нього обов'язковий крок.

**Що НЕ з'ясовано:** причина браузерного OAuth у вимірі 2026-09-14. Обидві точки лишаються
в `docs/19` §D.4 без арбітражу — свідомо.

## 3. Завдання B — Claude Code на A8 (крок D.3)

Мета: `claude -p` на A8 відповідає без `401`, під користувачем `agent`.

- `claude setup-token` вимагає браузера. З'ясуй **робочий** спосіб на headless-машині:
  чи дає CLI URL, який можна відкрити на T470; чи переноситься каталог креденшалів; чи
  потрібен інший механізм. **Не вигадуй** — перевіряй і фіксуй дослівний вивід.
- Той самий токен окремо кладеться у GitHub Secret `CLAUDE_CODE_OAUTH_TOKEN`, якщо
  `ai-fix.yml` лишається запасним шляхом.

⚠ **Це те саме значення, недійсність якого коштувала п'яти падінь тріажу і тижня простою**
(`401 Invalid bearer token`, чотири спростовані гіпотези). Тому:

- перевірка успіху — **дослівний вивід** робочого виклику, не «наче працює»;
- запиши **строк дії і процедуру поновлення** (`PROGRESS.md` §4.9 — життєвий цикл токенів).
  Токен, що протухає без сигналу, зупинить демон так само тихо, як тоді зупинив тріаж.

## 4. Завдання C — `agy` на A8

Той самий зонд, що вже є. Запускати **з довіреної теки на A8**:

```bash
ssh a8-lan
cd ~/hart && tools/scripts/check-agy-headless.sh
```

Далі — строго за таблицею exit-кодів (`docs/19` §D.4). Зокрема не плутай **1** (інструменти
заблоковані allow-list'ом) з **2** (потрібен браузер): перше лікується `permissions.allow`,
друге — перелогіном, і сплутати їх легко, бо заблокований інструмент валить `agy` тихо.

**Передумова:** репозиторій має бути на A8 під користувачем `agent`. Якщо його немає —
клонуй і додай шлях у `trustedWorkspaces` на A8 (там свій `settings.json`, не той, що на T470).

**Не розширюй** `permissions.allow` до `command(git)` / `write_file(*)` — прямо застережено
в `agy-orchestration-recommendations.md` §3.

## 5. Критерії виходу — числові

1. На A8 під `agent`: `tools/scripts/check-agy-headless.sh` → **exit 0**, дослівний вивід у PR.
2. На A8 під `agent`: тривіальний `claude -p` повертає відповідь **без `401`**, дослівно.
3. Зонд із `~/hart-wt/<worktree>` → **exit 0**, не 7 — на T470 **і** на A8.
4. Строк дії обох токенів і процедура поновлення записані в `PROGRESS.md` §4.9
   операційного репозиторію A8 (див. §1), закомічені й запушені — не лише на диску.

Не «виглядає працюючим» — ці чотири пункти з дослівним виводом.

1. **Чи лишається `ai-fix.yml` запасним шляхом** — від цього залежить, чи оновлювати
   GitHub Secret `CLAUDE_CODE_OAUTH_TOKEN`, чи токен потрібен лише на A8.

   правило так, щоб воно перевірялось, а не пам'яталось.
