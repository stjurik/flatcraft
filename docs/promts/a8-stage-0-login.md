## 1. Стан на момент старту — не перевідкривай

**D.4 закритий наполовину, і важливо розуміти, якою саме.** PR #108 дав вердикт
**✅ PASS на T470** (`~/hart`, 2026-09-13, exit 0, nonce повернувся дослівно, 0 входжень
`soft-denying`). Це доводить, що **механіка** headless-виклику працює: `agy -p` стартує,
читає `read_file`, пише `write_file`, нічого стороннього не чіпає.

Чого це **не** доводить: креденшали на T470 отримані через браузер. На A8 браузера немає,
і саме **логін** там досі відкритий. Різниця з тим, що було раніше: замість трьох варіантів
«спробуйте по черзі» тепер одна команда з однозначним exit-кодом.

**Той самий блокер стоїть і перед D.3** (`claude setup-token` на A8). У `PROGRESS.md`
A8-репозиторію це §4.10: «спосіб передачі OAuth-кодів не описаний ніде, блокує D.3».
**Обидва кроки — одна проблема:** браузерний OAuth на машині без браузера. Розв'яжеш раз —
знімеш обидва.

**Готові інструменти, не переписуй:** `check-agy-headless.sh` (вердикти 0-8),
`check-agy-scope.sh` (baseline-guard), `check-deny-parity.sh`, `prove-red-before-green.sh`.

## 2. Завдання A — межа worktree (розв'язати ДО того, як з'явиться демон)

PR #108 знайшов конфлікт, який ламає ADR-039 на рівні конструкції:

- ADR-039 §2 будує ізоляцію на «власному git-worktree на задачу»;
- `autorun.sh` тримає worktree у `$HOME/hart-wt` (`WT_ROOT`);
- `trustedWorkspaces` у `~/.gemini/antigravity-cli/settings.json` = `~/hart` + `~/lun_monitor`;
- перевірено: запуск зонда з `~/hart-wt/...` → **exit 7**.

Тобто **Gemini-пул і worktree-ізоляція сьогодні взаємовиключні**. Демон із Стадії 1 працює
саме через worktree на задачу — отже без цього рішення другий квотний пул у автономному
режимі не існує, а ADR-039 §5 («резерв при вичерпаній Claude-квоті») зводиться до паузи.

**Порядок перевірки — спочатку дешевший варіант, потім дорожчий.**

**A.1. Спробуй (а): додати `$HOME/hart-wt` у `trustedWorkspaces`.** Один рядок, тривіально
оборотний. Аргумент, чому це не розширення довіри по суті: `~/hart-wt` містить **чекаути
того самого репозиторію**, на який `agy` уже має повну довіру через `~/hart`. Тобто межа
ширша формально, а не фактично.

Перевірка — не «рядок додано», а зонд:

```bash
tools/scripts/autorun.sh --help 2>/dev/null || true   # переконайся, який WT_ROOT чинний
cd ~/hart-wt/<будь-який-worktree> && ~/hart/tools/scripts/check-agy-headless.sh
# очікувано: exit 0, а НЕ 7
```

**A.2. Якщо (а) відкинуто — тоді (б): `~/hart/.worktrees/`.** Це ★ з PR #108, але він дорожчий,
і його ціна має бути виміряна, а не припущена: вкладений worktree — це **повна копія репо
всередині репо**, і кожен інструмент, що ходить деревом, побачить її подвійно.

Обов'язкові виключення: `.gitignore`, `.prettierignore`, ignore в eslint-конфізі, `tsconfig`
exclude, `turbo`. Плюс `AUTORUN_WT_ROOT` за замовчуванням у `autorun.sh`.

**Доказ, що нічого не зламалось — числовий, до і після створення worktree:**

```bash
# ДО
pnpm exec prettier --check . 2>&1 | tail -3
pnpm exec eslint . --max-warnings=0 2>&1 | tail -3
# створити worktree всередині .worktrees/, повторити — числа мають збігтись
```

Розбіжність у кількості перевірених файлів = виключення не спрацювали.

**Рішення записати у PR як факт із доказом**, а не як вибір із двох слів.

## 3. Завдання B — Claude Code на A8 (крок D.3)

Мета: `claude -p` на A8 відповідає без `401`, під користувачем `agent`.

- `claude setup-token` вимагає браузера. З'ясуй **робочий** спосіб на headless-машині:
  чи дає CLI URL, який можна відкрити на T470; чи переноситься каталог креденшалів; чи
  потрібен інший механізм. **Не вигадуй** — перевіряй і фіксуй дослівний вивід.
- Той самий токен окремо кладеться у GitHub Secret `CLAUDE_CODE_OAUTH_TOKEN`, якщо
  `ai-fix.yml` лишається запасним шляхом.

⚠ **Це те саме значення, недійсність якого коштувала п'яти падінь тріажу і тижня простою**
(`401 Invalid bearer token`, чотири спростовані гіпотези). Тому:

- перевірка успіху — **дослівний вивід** робочого виклику, не «наче працює»;
- запиши **строк дії і процедуру поновлення** (`PROGRESS.md` §4.9 — життєвий цикл токенів).
  Токен, що протухає без сигналу, зупинить демон так само тихо, як тоді зупинив тріаж.

## 4. Завдання C — `agy` на A8

Той самий зонд, що вже є. Запускати **з довіреної теки на A8**:

```bash
ssh a8-lan
cd ~/hart && tools/scripts/check-agy-headless.sh
```

Далі — строго за таблицею exit-кодів (`docs/19` §D.4). Зокрема не плутай **1** (інструменти
заблоковані allow-list'ом) з **2** (потрібен браузер): перше лікується `permissions.allow`,
друге — перелогіном, і сплутати їх легко, бо заблокований інструмент валить `agy` тихо.

**Передумова:** репозиторій має бути на A8 під користувачем `agent`. Якщо його немає —
клонуй і додай шлях у `trustedWorkspaces` на A8 (там свій `settings.json`, не той, що на T470).

**Не розширюй** `permissions.allow` до `command(git)` / `write_file(*)` — прямо застережено
в `agy-orchestration-recommendations.md` §3.

## 5. Критерії виходу — числові

1. На A8 під `agent`: `tools/scripts/check-agy-headless.sh` → **exit 0**, дослівний вивід у PR.
2. На A8 під `agent`: тривіальний `claude -p` повертає відповідь **без `401`**, дослівно.
3. Зонд із worktree (за обраним варіантом A.1 або A.2) → **exit 0**, не 7.
4. Для варіанта (б): `prettier --check .` і `eslint .` дають **однакову кількість файлів**
   до і після створення worktree.
5. Строк дії обох токенів і процедура поновлення записані — у `PROGRESS.md` §4.9 або в
   `docs/19` §D.3, залежно від того, куди вирішено (див. §7).

Не «виглядає працюючим» — ці п'ять пунктів із виводом.

## 7. «Опитування» — винести в PR

1. **Варіант межі worktree** — (а) чи (б), з виміряною ціною кожного, а не з переказу.
2. **Куди пише операційний стан A8.** Документи A8 (`PROGRESS.md`, `A8_UBUNTU_INSTALL.md`,
   `files/`) живуть у локальній теці поза git. Рішення yurii — приватний репозиторій
   `a8-ops`. Доки його немає, записи про логіни й токени не мають куди лягти: назви місце
   явно, не клади «поки що сюди».
3. **Чи лишається `ai-fix.yml` запасним шляхом** — від цього залежить, чи оновлювати
   GitHub Secret, чи токен потрібен лише на A8.
