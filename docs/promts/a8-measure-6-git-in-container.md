## 3. Вимір №6 — головне

**Питання.** Чи працює git усередині контейнера агента. Демон Стадії 1 робить там
`worktree add`, `commit` і `push`; жодна з цих операцій ніколи не перевірялась.

**Що вже відомо** (уточнено 2026-09-17, з твого ж звіту М-3):

```
lefthook prepare → git config --global --add safe.directory /repo → exit status 128
```

`safe.directory` у репозиторії не згадується ніде (перевірено) — команду запускає сам
`lefthook`, і запускає тому, що спрацювала перевірка **dubious ownership**. А падає вона на
**записі** в `~/.gitconfig`. Тобто дві гіпотези — чужий власник і недоступний `HOME` — **не
альтернативні, а послідовні**: чужий власник → стандартний ремонт → ремонту нема куди писати.

**Передбачення, записане ДО прогону.** Правило — `docs/16` §8.2 п.2 (промпт помилково посилався
на «§2.2», якого не існує; виправлено). Дослівно: очікування записується **до** запуску і після
не міняється.

1. у контейнері зламаний не `prepare`, а git загалом;
2. `git commit` впаде **ще й окремо** — через відсутню identity, бо `user.email`/`user.name`
   зазвичай живуть у глобальному конфігу, який недоступний.

**Чого досі ніхто не бачив.** Сигнатура `exit status 128` відома лише **через `lefthook`** — це
його повідомлення про чужу невдачу, а не вивід git. Дослівного stderr самої команди немає в
жодному звіті. Саме він назве причину одним рядком (`$HOME not set` / `could not lock config
file` / `dubious ownership`), тому перехоплюй його явно.

### Три варіанти, а не два — UID і HOME треба розділити

У М-3 контейнер працював **під root** (видно з §9 п.6 звіту PR #110). Пара «root проти
`--user 1002:1002`» здається природною, але вона міняє **дві** змінні одразу: власника **і**
`HOME`. У `node:22` для UID 1002 немає запису в `/etc/passwd`, тому Docker виставить `HOME=/`,
а `/` непридатний для запису — і `git config --global` впаде з **іншої** причини, ніж
неспівпадіння власника. Це `docs/16` §8.2 п.4.

| Комірка | Запуск                                                             | Власник репо  | `HOME`        | Що ізолює                                   |
| ------- | ------------------------------------------------------------------ | ------------- | ------------- | ------------------------------------------- |
| **A**   | дефолтний root                                                     | не збігається | `/root`, пише | чи ламає сама невідповідність власника      |
| **B**   | `--user 1002:1002`                                                 | збігається    | `/`, не пише  | наївний «фікс» — відтворення другої причини |
| **C**   | `--user 1002:1002 -e HOME=/tmp/agenthome` (тека створена, `chown`) | збігається    | пише          | **вирішальна**: обидві причини зняті        |

Читання: якщо в **C** усе зелене — вимога до образу «збіг UID + записуваний HOME», і внесок
кожної половини видно з A і B. Якщо **C** усе одно червона — причина третя, і її назве дослівний
stderr.

**Контроль на вірність відтворення (прийнято з твого плану).** Дослівний `docker run` із М-3 не
зберігся, тож першим критерієм став збіг сигнатури: якщо комірка **A** не відтворює
`git config --global --add safe.directory /repo → 128`, ти міряєш **інший** контейнер — скажи це
прямо, а не підставляй висновок. І цього разу **збережи дослівну команду `docker run`** у звіті
(`docs/16` §8.2 п.5) — саме її відсутність створила цю проблему.

**Процедура.** Контейнер як у М-3 (стоковий образ + `uv`/`pnpm`, Python 3.12, `ro`-монтування за
звуженим списком), під `agent` на A8. Сім команд — у **кожній** з трьох комірок. Дослівний вивід
кожного рядка:

```bash
id; echo "HOME=$HOME"; ls -ld "$HOME"
touch "$HOME/.probe" && echo HOME_WRITABLE || echo HOME_READONLY
git config --global --add safe.directory /repo 2>&1; echo "exit=$?"
git -C /repo status 2>&1 | head -3; echo "exit=$?"
git -C /repo worktree add /tmp/wt-probe -b probe/gitcheck 2>&1 | tail -3; echo "exit=$?"
git -C /tmp/wt-probe commit --allow-empty -m probe 2>&1 | tail -3; echo "exit=$?"
git -C /tmp/wt-probe -c user.email=probe@local -c user.name=probe \
    commit --allow-empty -m probe2 2>&1 | tail -3; echo "exit=$?"
```

⚠ **Два останні рядки — пара з контролем.** Той самий `commit` без явної identity і з нею.
Якщо перший падає, а другий проходить — причина в identity, а не у власності чи в `HOME`. Без
цієї пари три різні причини зіллються в одне «git не працює», і лікувати будемо не те.

⚠ **`push` не міряй у цьому прогоні.** Він потребує креденшала і вихідної мережі — це два
додаткові невідомі, які зіпсують читання решти. Якщо чотири кроки вище зелені, `push`
перевіряється окремо; якщо червоні — `push` однаково недосяжний.

**Що зробити далі за результатом:**

- **Усе зелене** — вимір №6 закритий, Стадія 1 стартує без невідомих у git-шарі.

### Куди лягає запис — питання вирішено, робимо як ти запропонував

Приписка «записати в `docs/20`» була дефектом промпту: цього файлу немає в `main`, і внести
його в гілку, авторизовану під два рядки ADR-038, означало б зміну **значно більшу за
авторизовану**. Твоє рішення приймається без правок:

- повний протокол → новий `docs/promts/inputs/measurement-6-git-in-container.md` (конвенція
  `stage-1-step-0-measurements.md`);
- звіт за формою §6 → тіло draft PR;
- рядок для таблиці вимірів `docs/20` — **готовим текстом у звіті**, щоб його вніс той, хто
  мерджитиме гілку планування.

Те саме стосується `docs/16` §8.1 і §8.2: вони теж поки лише в гілці планування. Читай, застосовуй,
але **не посилайся на них як на чинний `main`** — цитуй зміст, а не номер розділу.

- **Щось червоне** — назвати **точну** причину з дослівного рядка і сформулювати вимогу до
  образу: UID користувача = власник примонтованого репо **або** `safe.directory` доданий на
  етапі побудови; `$HOME` існує і записуваний; git-identity задається явно (репо-локально або
  `GIT_AUTHOR_*`/`GIT_COMMITTER_*`). **Вимогу формулюй після виміру, не до** — інакше це знову
  здогад, оформлений як факт.
- Прибери за собою: `/tmp/wt-probe`, гілка `probe/gitcheck`, `$HOME/.probe`.
