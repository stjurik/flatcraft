B. ADR-039 «Автономне середовище розробки на A8» — головний деліверабл

Має зафіксувати:

1. **Лінію розділу:** GitHub Actions = детерміновані оракули; A8 = недетерміновані
   агенти. Обґрунтування — з інспекції B і з історії п'яти падінь тріажу.
2. **Ізоляцію замість підтверджень:** контейнер, окремий користувач, worktree на
   задачу, allowlist вихідної мережі, `--dangerously-skip-permissions` дозволений
   ЛИШЕ всередині контейнера. Явно: на A8 немає пароля vault, SSH-ключа до Mirohost і
   GHCR-токена на запис → `deploy-staging.yml` і `release.yml` лишаються на
   GitHub-hosted.
3. **Оркестратор:** тонкий детермінований супервізор + свіжа сесія на задачу. Стан —
   у git і черзі на диску, ніколи в контексті моделі. Обґрунтування: довгі сесії
   дорогі (>150k контексту) і втрачають стан при падінні.
4. **Класифікатор виходу** з трьома класами і реакціями: квота → пауза до вікна;
   `401 / authentication_failed` → STOP + сповіщення yurii (потрібен інтерактивний
   логін); інше → `failed` + журнал. Сигнатури взяти з реальних логів (Master Run
   10/11), не вигадувати.
5. **Два квотні пули:** Claude — write-роботи; `agy`/Gemini — read-only (тріаж,
   рев'ю, інвентаризації) і резерв, коли Claude-вікно вичерпане.
6. **Протокол питань до yurii:** клас A (незворотне / зміна контракту — без дефолту,
   агент чекає) і клас B (є ★ і дефолт, таймер 6–12 год). Обов'язкові поля питання:
   питання / варіанти / наслідок кожного / ★ / дефолт / оборотність. Питання без
   заповнених полів не відправляється. Бюджет питань на run. Канали Discord — чотири,
   за `docs/19` D.6.
7. **Запобіжники:** kill switch, денний ліміт задач, журнал кожного прогону на диску.
8. **Метрики самовдосконалення:** покриття оракулами (частка задач, приймання яких
   доведене програмою, а не твердженням); якість питань (скільки з них yurii позначив
   як «можна було дефолтом»); `agy-stats`; правило пост-мортему — клас помилки, що
   повторився тричі, автоматично породжує задачу на зміну процесу (це §0 п.6,
