## 2. Завдання A — `tools/scripts/check-agy-scope.sh` + `.test.sh`

Механізує правило «після КОЖНОГО виклику `agy` — `git status`, змінитись мав лише
доручений файл». Зараз це ручний ритуал; двічі його недотримання коштувало відкату
(`agy-orchestration-recommendations.md` §4, інциденти Master Run 8).

- Стиль дослівно як `check-forbidden-paths.sh`: читає `git status --porcelain` зі
  stdin, `set -euo pipefail`, `::error::`, exit 1.
- Дозволена зона запису — `docs/promts/inputs/**`. Будь-що поза нею → exit 1 зі
  списком файлів і готовою командою `git restore`.
- **Не відкочуй сам** — свідомо: автовідкат знищив би незбережену роботу, якщо
  запустити не в той момент. Скрипт дає факт і точну команду, рішення — за людиною.
- `.test.sh`: чисто → 0; запис у `docs/promts/inputs/` → 0; запис у
  `docs/15_LLM_PROMPTS.md` → 1 (це дослівно інцидент Master Run 8); кілька сторонніх
  файлів → 1 з повним списком.

## 3. Завдання B — `tools/scripts/check-agy-headless.sh` + `.test.sh` + РЕАЛЬНИЙ D.4

Одна команда, що відповідає на питання: **чи може непильнований агент викликати
Gemini на цій машині.** Перевіряй увесь ланцюг, потрібний оркестратору, а не «чи
щось надрукувалось».

Три капкани, які ти МУСИШ врахувати (не перевідкривай їх — вони задокументовані):

1. `agy -p` **не читає stdin** — передавай контекст файлом, проси читати `read_file`;
2. будь-який bash-виклик поза allow-list'ом **тихо падає**
   (`soft-denying tool confirmation "Bash"`) і `agy` завершується без результату —
   це легко сплутати з проблемою логіна. Забороняй bash явно в промпті;
3. `write_file(*)` ширший за задум — звіряй `git status` до і після (через скрипт
   із завдання A).

**Механіка зонда.** Покласти у `docs/promts/inputs/_agy-probe-input.md` унікальний
nonce → попросити `agy` прочитати його через `read_file` і записати у
`_agy-probe-output.md` → звірити. Префікс `_` — наявна конвенція транзитних файлів
(`_review.diff`); обидва видали в кінці. Запускай під `timeout` і з `--log-file`,
щоб сигнатури відмов лишились у лозі.

**Класифікація** — кожна гілка окремим тестом:

| Спостереження                      | Вердикт                                            |
| ---------------------------------- | -------------------------------------------------- |
| Вихідний файл містить nonce        | ✅ PASS — Gemini-пул на A8 можливий                |
| У лозі `soft-denying`              | ❌ інструменти заблоковані → allow-list, не логін  |
| У виводі URL логіна / `sign in`    | ⚠️ потрібен браузер → варіанти 2-3 `docs/19` §D.4  |
| `401` / `unauthorized` / `API key` | ❌ креденшали недійсні                             |
| exit 124                           | ❌ таймаут                                         |
| Файл є, nonce немає                | ❌ агент відповів, але завдання не виконав         |
| Зміни поза `docs/promts/inputs/**` | ⚠️ scope-creep — повторення інциденту Master Run 8 |

`.test.sh` кладе у `PATH` фальшивий `agy`-стаб, який імітує кожен рядок таблиці.
Додай мутаційну перевірку: зламай класифікатор — тест мусить впасти. Так вердиктна
логіка буде перевірена навіть у гілках, яких реальний прогін не зачепить.

**Далі — головне, заради чого цей run потрібен саме на твоїй машині: ПРОЖЕНИ ЗОНД
ПО-СПРАВЖНЬОМУ.** У звіті наведи **дослівний** вивід (verify-then-write,
CLAUDE.md §0 п.3), не переказ. Якщо вердикт не PASS — пройди варіанти 2-3
`docs/19` §D.4 по черзі й запиши, який спрацював. Якщо жоден — так і напиши:
негативний результат тут цінніший за вигаданий позитивний, бо він чесно закриває
ADR-039 §5 і знімає половину обґрунтування A8.
