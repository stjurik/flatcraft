# Вхід рев'ю №2 — скрипти і тести демона черги A8

**Роль для тебе:** незалежний Рев'юер. **Обмеження:** не виконуй bash (тихо відхиляється), читай лише `read_file`. Пиши **виключно** у `docs/promts/inputs/agy-a8-daemon-2-output.md`. Кожне фактичне твердження — з файлом і номером рядка. Чого не можеш перевірити читанням — пиши «не перевіряється читанням».

## Пари «код → тест»

| Код                                              | Тест                                    |
| ------------------------------------------------ | --------------------------------------- |
| `tools/scripts/a8-tick-logic.sh`                 | `tools/scripts/a8-tick-logic.test.sh`   |
| `infra/ansible/roles/a8/templates/a8-tick.sh.j2` | `tools/scripts/a8-tick.test.sh`         |
| `tools/scripts/a8-ro-shell.sh`                   | `tools/scripts/a8-ro-shell.test.sh`     |
| `tools/scripts/check-hook-loud.sh`               | `tools/scripts/check-hook-loud.test.sh` |

Кожен тест має в кінці блок мутацій: копія коду ламається виразом `sed`/`perl`, і набір мусить почервоніти.

## Одне питання

**Чи є сценарій, за якого тест зелений, а логіка зламана?** Для кожної пари шукай:

1. Фікстуру, у якій два значення, що їх розрізняє код, **збігаються**, тож тест пройде на будь-якому з двох варіантів коду.
2. Перевірку, що проходить «з неправильної причини», наприклад `!grep` по файлу, якого не існує.
3. Мутацію, яка вбивається не тим сценарієм, заради якого написана (зламано одне, а впало інше).
4. Поведінку, яку код має, а жоден сценарій не перевіряє (назви рядок коду без покриття).
5. Для `a8-ro-shell.sh` — рядок `SSH_ORIGINAL_COMMAND`, що пройде перевірки і виконає запис або прочитає файл, якого не мав би.

## Формат

По розділу на пару. У кожному — список знахідок: «рядок коду / рядок тесту → сценарій → чому тест зелений». У кінці — «Що я не зміг перевірити читанням».
