# Вердикти по таблиці §2 (18 рядків):

1. **ДОВОДИТЬ**. Якщо agent має sudo, не в групі docker, або має правило в sudoers — V1 впаде.
2. **ДОВОДИТЬ**. Перевіряється `stat` (існування, тип директорії, власник `a8_agent_user`).
3. **ДОВОДИТЬ**. Точково перевіряє `hasTrustDialogAccepted=true` саме для ключа кореня клону в json.
4. **ЧАСТКОВО**. V4 доводить фізичну наявність скрипта/конфіга і відсутність стоп-файла _під час перевірки_, але не може довести, що вони там з'явились _до_ демона.
5. **ДОВОДИТЬ**. V5 підкладає STOP-файл і перевіряє, що виклик guard дає `exit=10`.
6. **ДОВОДИТЬ**. V5c/V5d підміняє ліміт та файл станів і ловить відповідні коди 11 і 12.
7. **ДОВОДИТЬ**. V8d перевіряє fail closed (відмову при `whatever`) та кількість полів у записі.
8. **ЧАСТКОВО**. V6 перевіряє, що контейнер має UID=`a8_container_uid`, але не доводить, що цей UID належить власнику репо (власник перевіряється в V2 за іменем `pw_name`, а не за конкретним числом 1002).
9. **ДОВОДИТЬ**. Робить `touch "$HOME/.a8probe"` в середині контейнера.
10. **ДОВОДИТЬ**. `git var GIT_AUTHOR_IDENT` дійсно перевіряє кінцеву identity.
11. **ДОВОДИТЬ**. `test -t 0` в контейнері зловить наявність TTY.
12. **ЧАСТКОВО**. Перевіряє досяжність `lefthook` у контейнері. Якщо залежності (`node_modules`) ще не встановлені на хості, тест впаде, хоча сам `PATH` може бути коректним.
13. **ДОВОДИТЬ**. `swapon --show` та перевірка значення `vm.swappiness` (10).
14. **ЧАСТКОВО**. Перевіряє наявність параметрів у `daemon.json`, але не доводить, що процес dockerd їх фактично прийняв (якщо `systemctl restart` відкладений чи впав).
15. **ЧАСТКОВО**. V9 доводить, що ipset наповнено і таймер `enabled`, але не перевіряє, що `DROP` працює (як і визнано в самому README).
16. **НЕ ДОВОДИТЬ**. V11 — це просто `debug` (вивід інформації). Assertion відсутній, тому він ніколи не почервоніє при зламаній вимозі.
17. **ДОВОДИТЬ**. Робить реальну спробу `touch` у ro-шляхи і чекає на відмову (EROFS).
18. **ДОВОДИТЬ**. Перевіряє наявність відповідної змінної оточення (`UV_PYTHON`) у контейнері.

# Додаткові питання:

1. **a8-egress-rules.sh.j2**: Так, арифметика схибить, якщо в ланцюзі буде правило iptables із коментарем (`-m comment --comment "RELATED,ESTABLISHED"`) або подібною ціллю. awk зматчить цей рядок, і позиція обчислиться хибно.
2. **a8-guard.sh.j2**: `sed 's/[[:space:]]*$//'` видаляє пробіли лише в кінці. Якщо в файл потрапить запис із пробілом на початку (` failed`), `grep '^failed$'` його не знайде. Також при race condition може бути `failedfailed\n`.
3. **Ідемпотентність**: Зламається повторне ввімкнення `swap`, якщо хтось зробив `swapoff /swapfile`. Перевірка `when: not a8_swap_stat.stat.exists` побачить, що файл існує, і пропустить `swapon` (конфіг роз'їдеться з реальністю).
4. **Припущення за факт**:
   - У `verify.yml` (V13): _"М-3: node:22 несе CPython 3.14..."_ — це вигадка, оскільки CPython 3.14 ще не випущено, і node:22 не може його нести зараз.
   - У `verify.yml` (V6b): _"Ця межа тримається, доки сокет docker НЕ змонтовано..."_ — припущення, що інших шляхів підвищення привілеїв немає.
   - (Авторське, визнане) У `README.md` §6: _"для ufw reload — висновок, не вимір"_.
